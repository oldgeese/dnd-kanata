# dnd-kanata 設計書

- 作成日: 2026-10-28
- ステータス: レビュー待ち

## 1. 背景と目的

D&D 5版のキャラクターシートサイト [dndjp.sakura.ne.jp](https://dndjp.sakura.ne.jp/)（以下「元サイト」）は、
表示ページ（`OUTPUT.php`）と編集ページ（`INPUT_FORM.php`）が分かれており、編集のたびに編集画面へ移動し、明示的に保存操作をする必要がある。

dnd-kanata は、元サイトのキャラクターデータを取り込んでコピーを持ち、
**1つの画面で表示とその場編集（自動保存）ができる**別サイトを提供する。

### 成功基準

- 元サイトの URL または ID を入力するだけでキャラクターを取り込める。
- シート画面で値をクリック／タップしてその場で書き換えられ、保存操作なしで保存される。
- 能力値などを変えると、修正値・技能値などの派生値が元サイトと同じ結果で即座に再計算される。
- 必要なときだけ、編集内容を元サイトへ手動で書き戻せる。
- 卓の仲間がそれぞれ自分のキャラクターを管理でき、閲覧用リンクで他人に見せられる。

## 2. 決定事項の要約

| 論点 | 決定 |
|---|---|
| 元サイトとの同期 | 基本は一方向（取り込み後は dnd-kanata が正）。必要なときだけ手動で書き戻す |
| 利用者 | 卓の仲間を含む複数ユーザー |
| リアルタイム性 | 自分の画面での即時反映と自動保存。他人の画面への即時反映は要件外 |
| バックエンド | Firebase Realtime Database |
| 取り込み・書き戻しの実行場所 | Cloud Functions（Blaze プラン利用中） |
| 元サイトのパスワード | 書き戻しのたびに入力。どこにも保存しない |
| 自動計算 | 元サイトが計算している基本的な派生値のみ。ルールデータ（呪文・装備マスター）は持たない |
| フロントエンド | React + Vite + TypeScript、Firebase Hosting |
| 認証 | Firebase Authentication（Google ログイン、メールリンクによるパスワードなしのログイン） |
| 共有 | キャラクターごとの閲覧用リンク（推測できない ID、ログイン不要の読み取り専用） |

## 3. 元サイトの調査結果

- `INPUT_FORM.php?ID={id}` はログインなしで取得でき、`input` / `textarea` / `select` に現在値が入っている。項目数は数百（`str_base`、`char_level`、`STR_PROF_ST_CHK` など）。取り込み元にはこのページを使う。
- 保存は `OUTPUT.php?ID={id}` への POST で、`password` 項目にキャラクターごとのパスワードが必要。
- 文字コードは Shift_JIS（`content-type: text/html; charset=SJIS`）。
- CORS ヘッダーがないため、ブラウザから直接は取得できない。
- 派生値の計算は `dddb5e.js`（約 640 行）で行われている。

## 4. 全体構成

```
[ブラウザ: React + Vite + TS]  ──読み書き──▶  [Firebase Realtime Database]
        │  Google ログイン（Firebase Auth）
        │
        └─呼び出し─▶ [Cloud Functions]
                        ├ importSheet(sourceId)        … INPUT_FORM を取得し、SJIS→UTF-8 に変換して解析
                        └ writeBack(sheetId, password) … 全項目を SJIS で OUTPUT.php に POST
```

### ユニット

| ユニット | 責務 | 依存 |
|---|---|---|
| `rules/`（共有パッケージ） | `fields` から派生値を計算する純粋関数 | なし |
| `functions/import` | 元サイトの取得・文字コード変換・フォーム解析・保存 | `rules/`（任意）、Firebase Admin |
| `functions/writeBack` | 送信内容の組み立て・SJIS エンコード・POST・結果判定 | `rules/`、Firebase Admin |
| `web/` | 一覧・シート画面・その場編集・自動保存・共有設定 | `rules/`、Firebase SDK |

`rules/` は画面と書き戻しの両方で同じコードを使う。

## 5. データモデル（Realtime Database）

```
/sheets/{sheetId}            sheetId はランダムな UUID（推測できない ID）
    ownerUid: string
    sourceId: number         元サイトのキャラクター ID
    shared: boolean          閲覧用リンクの有効／無効
    fields: { [元サイトの項目名]: string }
    schema: { [項目名]: { kind, order, options?, checkedValue?, readonly? } }
                             取り込み時点のフォーム項目の定義（入力欄の種類、選択肢、チェック時の値、並び順）。
                             画面の入力欄の種類決定と、書き戻し時の変更検知に使う
    sourceLastUpdate: string 取り込み時点の元サイトの last_update（書き戻し時の変更検知用）
    importedAt: number
    updatedAt: number
/users/{uid}/sheets/{sheetId}: true   自分のキャラクター一覧用インデックス
```

- 項目名は元サイトのものをそのまま使う。書き戻し時の名前の変換を不要にするため。
- 値はすべて文字列で保持する（元フォームの値をそのまま往復させるため）。数値として扱うのは `rules/` の中だけとする。
- 派生値は保存せず、表示時と書き戻し時に計算する。
- 元サイトの項目名に Realtime Database のキーで使えない文字（`. $ # [ ] /`）が含まれる場合は、取り込み時に可逆なエスケープをかける（実装時に実データで確認する）。

## 6. 画面とその場編集

### ルート

- `/`：ログインと自分のキャラクター一覧。「元サイトの URL／ID から取り込む」ボタン。
- `/c/{sheetId}`：表示と編集を兼ねたシート画面（持ち主のみ）。
- `/s/{sheetId}`：閲覧専用のシート画面（`shared == true` のとき誰でも閲覧可）。

### シート画面

- セクションは元サイトと同じ順に並べる（基本情報、能力値、セーヴ・技能、戦闘、攻撃、人物像、所持品、特徴・特技、呪文）。
- 普段は読みやすい表示にし、項目をクリック／タップするとその場で入力欄に変わる。フォーカスが外れるか Enter で確定する。
- 項目の種類ごとの編集方法:
  - 数値: 入力欄。所持金には「±」ボタンを付ける。現在 HP は、量を入力して「ダメージ」「回復」ボタンでも更新できる（ダメージは一時 HP から先に減らす）。
  - 長い文章: 高さが自動で伸びるテキストエリア。
  - 習熟・呪文スロット: チェックボックス。クリックで即座に反映する。
  - 選択肢（属性・サイズなど）: プルダウン。
- 派生値は編集不可とし、マウスを重ねると内訳（例: 「DEX+4 / 習熟+4 / その他+0」）を表示する。元の値を変えると即座に再計算する。

### 自動保存

- 変更した項目だけを、入力が止まって約 0.5 秒後に `update` で書き込む。
- 画面上部に保存状態を表示する: 「保存中…」「保存済み」「オフライン（再接続時に送信）」「エラー（再試行）」。
- オフライン時は Realtime Database の書き込み待ちの仕組みに任せる。
- 同時編集の競合は項目単位で最後の書き込みを優先する（他人の画面への即時反映は要件外のため）。

### 対象外（YAGNI）

- 元に戻す（Undo）の履歴
- レイアウトのカスタマイズ
- ダイスロール
- チャットパレット生成
- 卓（グループ）単位の共有

## 7. 取り込み（`importSheet`）

1. 入力された URL／ID から数字の ID を取り出す。数字以外は受け付けない。
2. `https://dndjp.sakura.ne.jp/INPUT_FORM.php?ID={id}` だけを取得する（取得先は固定し、任意の URL へのアクセスに使われないようにする）。
3. CP932 から UTF-8 に変換し、HTML を解析して `input`（text / checkbox / hidden など）、`textarea`、`select` の名前と値を取り出す。`password` と送信ボタンは除外する。
4. 新しいシートとして保存し、`/users/{uid}/sheets` にも登録する。
5. 同じ `sourceId` を持つ自分のシートがすでにある場合は、確認したうえで `fields`・`schema`・`sourceLastUpdate` を丸ごと上書きする（差分の統合はしない）。
6. 存在しない ID の場合、元サイトは新規作成フォーム（hidden の `ID` が空）を返すので、`ID` の値が要求した ID と一致しなければ「見つからない」として扱う。

## 8. 書き戻し（`writeBack`）

1. 呼び出せるのはシートの持ち主だけとする。パスワードは画面で入力して渡す。
2. 書き戻す直前に `INPUT_FORM.php` を取得し、現在の項目名を `schema` と比べる。取り込み時になかった項目がある場合は中止し、警告を返す（元サイトの仕様変更で値を消さないため）。
   また、元サイトの `last_update` が `sourceLastUpdate` と異なる場合（取り込み後に元サイトで編集された場合）は、利用者が上書きを確認したときだけ続行する。
   CP932 で表せない文字（絵文字など）を含む項目がある場合は中止し、該当する項目を返す。
3. `fields` と `rules/` で計算した派生値を合わせ、元サイトと同じ項目名で CP932 にエンコードし、`OUTPUT.php?ID={id}` に POST する。
4. 返ってきた画面から、成功・パスワード違い・その他のエラーを判定して返す。
5. パスワードはログにも残さない。

## 9. 自動計算（`rules/`）

- 入力は `fields`、出力は派生値の一覧（項目名 → 値と内訳）。
- 対象: 元サイトの `dddb5e.js` で計算されている範囲（`calc_all()`・`CGP()`・`divideChange()` が書き込む項目）。具体的には能力値修正値、習熟ボーナス、セーヴ、技能、受動知覚、AC、イニシアチブ、移動速度、所持金と所持品の重量、能力値購入の残りポイント。
- 呪文セーブ難易度・呪文攻撃ボーナスは元サイトでも手入力の項目なので、計算しない。
- 計算式は `dddb5e.js` を移植し、同じ入力に対して元の `dddb5e.js` と同じ出力になることをテストで確かめる。

## 10. エラー処理

- 取り込み: ID が存在しない、元サイトが応答しない、フォームの形式が想定と違う、といった場合は理由を表示する。中途半端なデータは保存しない。
- 自動保存: 書き込みに失敗したら「エラー」を表示して再試行ボタンを出す。
- 書き戻し: パスワード違い、通信エラー、項目の変更検知を区別して表示する。失敗しても dnd-kanata 側のデータには影響しない。

## 11. 元サイトへの配慮

- アクセスは利用者がボタンを押したときだけとする（定期取得や一括取得はしない）。
- 1 ユーザーあたり、取り込みと書き戻しを合わせて 1 分に 5 回までに制限する。シート画面での編集（Realtime Database への直接書き込み）はこの制限の対象外とする。
- User-Agent にサイト名と連絡先（GitHub リポジトリの URL）を入れる。

## 12. セキュリティルール（Realtime Database）

- `/sheets/{sheetId}`: 持ち主（`ownerUid == auth.uid`）は読み書きでき、`shared == true` なら誰でも読める。
- `ownerUid` と `sourceId` は作成後に変更できない。シートの作成は Cloud Functions（Admin SDK）だけが行う。
- `/sheets` 全体の一覧取得は禁止する。
- `/users/{uid}` は本人だけが読める。書き込みは Cloud Functions だけが行う。

## 13. テスト

- `rules/`: 元サイトの `dddb5e.js` を jsdom 上で実データのフォームに対して実行した結果と、自前の計算結果が一致することを Vitest で確かめる（入力値を変えた多数のケースで比較する）。基準データには ID 54555 を使う。元サイトの HTML と JS はリポジトリに含めず、テスト前に取得スクリプトでダウンロードする。
- 取り込みの解析: 保存しておいた Shift_JIS の HTML から、正しく項目を取り出せることを確かめる。
- 書き戻し: POST する本文（項目名・値・CP932 エンコード）を確かめる。元サイトへの実送信は、自分のテスト用キャラクターに対してだけ手動で行う。
- セキュリティルール: Firebase Emulator で確かめる。

## 14. 配置

- 既存の Firebase プロジェクト（Blaze プラン）を使い、Firebase Hosting と Cloud Functions（Node.js、TypeScript）に配置する。
- リポジトリ: https://github.com/oldgeese/dnd-kanata
